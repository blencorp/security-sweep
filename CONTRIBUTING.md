# Contributing

Thanks for helping. This project keeps a narrow scope: critical vulnerabilities, smallest fix, provable footprint. Changes that widen what a fix may touch need a strong reason.

## Ground rules for code

- Python 3.9+ standard library only, in `skills/security-sweep/scripts/`. No third-party packages.
- Every network request and external tool run goes through `sweep/net.py`, so it can be recorded and replayed.
- Anything that cannot get an answer must raise `net.SourceError` (making the run INCOMPLETE), never return "nothing found".
- A package manager runs only in a scratch directory, in lockfile-only mode, with scripts and plugins disabled. The project directory is never a working directory for a tool.
- Keep `SKILL.md` short (under ~100 lines). Detail goes in `references/`.

## Tests

```bash
python3 -m unittest discover -s tests -t .
```

- `tests/test_versions.py`, `test_osv.py`, `test_cvss.py`, `test_lockfiles.py`: pure unit tests.
- `tests/test_fixtures.py`: runs `scan`, `plan`, `check`, `revert` and `report` against the sample projects in `tests/fixtures/`. By default they replay `tests/recordings/` with the clock pinned to `tests/recordings/RECORDED_AT`, so they are offline and deterministic.
- `SECURITY_SWEEP_LIVE=1 python3 -m unittest tests.test_fixtures` runs the same tests against live data, and also runs the prescribed npm and Composer commands in project copies to prove they match the computed footprint. A scheduled CI job does this daily.

### Refreshing recordings

```bash
python3 tests/record.py
```

This wipes `tests/recordings/`, runs every fixture test live with recording on, and writes `RECORDED_AT`. Always re-record everything in one session. The recordings share responses (OSV, KEV, registries), so partial re-recording mixes data from different days. Needs `npm`, `pnpm`, `yarn` and `composer` on `PATH`.

Fixture expectations come from real data. When data changes an answer (for example, a newer advisory makes a different version the smallest safe fix), check that the new answer is right, then update the test and say why in the commit. Guard assertions that will drift with `if not helpers.live():`.

### Adding a fixture

Put a minimal project in `tests/fixtures/<name>/`: a manifest, a lockfile generated by the real package manager with scripts disabled, and only the source files the scenario needs. Add a test class in `tests/test_fixtures.py`, then re-record.

## Agent check

`evals/agent-check/` runs coding agents with and without the skill on sample projects. It costs real agent sessions, so run it only for releases. See its README.

## Pull requests

- One change per PR, with tests.
- Update `CHANGELOG.md` under "Unreleased".
